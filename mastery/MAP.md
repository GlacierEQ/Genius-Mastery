# Mastery Map — Genius-Mastery (Kernel)

## Purpose

This repository is the **control kernel**, not a domain. Its mastery surface is the machinery that enables domain mastery elsewhere.

## Irreducible first principles

1. **Identity is hyphenated and singular** — `Genius-{purpose}` only.
2. **Claims must be falsifiable** — no “we understand X”.
3. **Evidence is first-class** — serious verification claims point to receipts.
4. **Counterevidence is retained** — never erased to look stronger.
5. **Mastery is a vector** — never a single percentage.
6. **Growth is open-ended** — core completion is not a curriculum ceiling.
7. **Composition is capability-based** — depend on IDs + evidence, not reputation.
8. **Aspiration ≠ verified capability** — label both honestly.
9. **Progress is state change** — planning is not execution and execution is not verification.
10. **Completion is executable** — the 1.0 core is complete only when `genius closure .` passes.

## Kernel capability dimensions

| Dimension | What “strong” looks like |
|---|---|
| foundations | Schema + contract rules are explicit and versioned |
| mechanisms | Validator, doctor, migration, challenge, composition, progress, and closure execute correctly |
| implementation | Tools run and produce deterministic machine-readable output |
| verification | Contract tests + evidence referential integrity + exact-head CI pass |
| operations | Upgrade paths preserve evidence and domain-authored artifacts |
| synthesis_transfer | Kernel generates independently self-validating descendants |
| composition | Family contracts resolve and execution receipts preserve provenance |
| learning | Counterevidence, calibration, outcomes, and frontier state feed the next spiral |
| original_work | New schema versions, migration functions, orchestration, and higher-order capability mechanisms |

## Verification boundary

Historical receipts in `evidence/ledger.jsonl` remain valid only for their recorded commits.

For the current 1.0 head:

- GitHub Actions `validate-contract` is the exact-head hosted verification surface.
- Buildkite `macos-self` is the independent native execution surface.
- Neither a release label nor this document is proof of either external run.
- `genius closure .` proves the repository's internal core-completion contract; external CI state remains separately observed evidence.
