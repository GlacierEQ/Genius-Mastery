# Mastery Map — Genius-Mastery (Kernel)

## Purpose

This repository is the **control kernel**, not a domain. Its mastery surface is the machinery that enables domain mastery elsewhere.

## Irreducible first principles

1. **Identity is hyphenated and singular** — `Genius-{purpose}` only.
2. **Claims must be falsifiable** — no “we understand X”.
3. **Evidence is first-class** — every serious capability claim points to receipts.
4. **Counterevidence is retained** — never erased to look stronger.
5. **Mastery is a vector** — never a single percentage.
6. **Growth is open-ended** — no curriculum ceiling.
7. **Composition is capability-based** — depend on IDs + evidence, not reputation.
8. **Aspiration ≠ verified capability** — label both honestly.

## Kernel capability dimensions

| Dimension | What “strong” looks like |
|---|---|
| foundations | Schema + contract rules are explicit and versioned |
| mechanisms | Validator, doctor, migration, composition resolve correctly |
| implementation | Tools run locally and produce machine-readable output |
| verification | Contract tests + referential integrity pass |
| operations | Upgrade path preserves evidence and domain artifacts |
| synthesis_transfer | Kernel can generate self-validating domain repos |
| original_work | New schema versions + migration functions |

## Current verified vs aspirational

- **Verified (local seed):** identity contract, core schemas, basic validator, doctor scaffold, composition file, family index stub.
- **Aspirational:** full migration engine, packaging/wheel, live GitHub Actions runs, cross-repo composition resolution at scale, automated freshness watchers.
